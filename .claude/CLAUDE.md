# Sea Radar — інструкції для Claude Code

## Призначення проєкту

Sea Radar — навчальний локальний вебзастосунок для показу суден у Дуврській протоці. Основний користувач — викладач, який демонструє карту курсантам. Це навчальний посібник, не інструмент навігації чи моніторинговий центр.

Вимоги замовника описані в `PROJECT_BRIEF.md`. Опис навчального формату, послідовності спринтів і checkpoint-ів — у `ABOUT.md`.

## Які вимоги застосовувати

- Для конкретної роботи спершу визнач її спринт і читай відповідний файл у `docs/tasks/` та його критерії приймання.
- Дотримуйся поступового розкриття вимог: не переглядай файли майбутніх спринтів або change request наперед, якщо користувач прямо не попросив цього. Не припускай майбутні вимоги.
- Якщо завдання спринту й `PROJECT_BRIEF.md` виглядають суперечливими, повідом про це та попроси уточнення, а не обирай вимогу мовчки.
- Для запису стану checkpoint використовуй `docs/checkpoints/TEMPLATE.md`, якщо цей файл доступний і завдання стосується checkpoint-а.
- Не вигадуй результати перевірок, статус сервісу AISStream або факт наявності реальних даних.

## Робочий процес

- Перед змінами оглянь релевантні файли та наявні домовленості проєкту; не роби непов'язаних рефакторингів.
- Працюй невеликими зрозумілими кроками, прив'язаними до критеріїв приймання поточного завдання.
- Перед завершенням запусти доречні тести, перевірки або збірку, визначені проєктом. У підсумку назви команди й фактичний результат; якщо перевірку не запускали або вона не пройшла — скажи про це прямо.
- Після змін переглянь diff і переконайся, що в нього не потрапили секрети, сторонні файли чи незапитані функції.
- Якщо бракує контексту або вимогу можна зрозуміти кількома способами, постав одне конкретне уточнювальне запитання до реалізації.

## Продуктові інваріанти

- Навчальні судна та їхні картки мають працювати без ключа AISStream і без доступу до джерела реальних даних.
- Ключ AISStream є секретом: не додавай його до вихідного коду, репозиторію, передаваних файлів, повідомлень, логів або інтерфейсу. Використовуй лише передбачений проєктом локальний спосіб конфігурації.
- Чітко розрізняй навчальні та реальні дані. Для реальних даних показуй час отримання, кількість отриманих суден і обмеження повноти; не подавай їх як повну картину району.
- Реальні судна — знімок, отриманий після запиту: не імітуй їхній рух між запитами. При помилці, обриві зв'язку чи відсутності повідомлень пояснюй ситуацію зрозуміло й не видавай її за успішний порожній результат.
- Не підмінюй невідомі значення нулями. Не відображай судно на карті без придатних координат; для повторних повідомлень використовуй найсвіжіше за часом, не дублюючи судно.
- Назви суден із зовнішніх даних вважай недовіреним текстом: відображай їх безпечно, не інтерпретуй як HTML або код.
- Зберігай локальний сценарій для одного користувача й одного фіксованого району. Не додавай без запиту автентифікацію, спільний сервер, хмарне розгортання, безперервний моніторинг, історію/відтворення, пошук/фільтри, сповіщення чи інші функції, прямо виключені з `PROJECT_BRIEF.md`.

## Середовище

`ABOUT.md` вказує Node.js 24, Git і Claude Code CLI як інструменти для роботи з проєктом. Перед запуском команд перевір актуальні scripts і налаштування в репозиторії та користуйся наявними командами замість припущень.
